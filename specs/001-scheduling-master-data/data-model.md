# Data Model: Scheduling Master Data Management

**Feature**: [spec.md](./spec.md) | **Plan**: [plan.md](./plan.md) | **Research**: [research.md](./research.md)

All identifiers are UUIDs generated by the application. Aggregate roots carry a `version: Int` for optimistic locking (R8). Table names are given in brackets.

## Overview

```text
School 1──* RoomFeature
School 1──* Room *──* RoomFeature
School 1──1 TimeGrid ── TeachingDay[*], TimeSlot[*] ── SlotDayExclusion[*]
School 1──* Subject *──* RoomFeature (required features)
School 1──* ClassLevel 1──* CurriculumEntry *──1 Subject
ClassLevel 1──* SchoolClass
Teacher *──* School (TeacherSchool)
Teacher *──* Subject (Qualification)
Teacher 1──* CommuteTime (pair of the teacher's schools)
Teacher 1──* Unavailability (day + TimeSlot)
UserAccount *──* School (account_school) ; UserAccount 1──1 PasswordCredential
```

### TimeGrid [`teaching_day`, `time_slot`, `slot_day_exclusion`] — part of School aggregate

**TeachingDay**: `(schoolId, dayOfWeek)` — set of `MONDAY..SUNDAY` (FR-004).

**TimeSlot**

| Field | Type | Rules |
|-------|------|-------|
| id | UUID | |
| schoolId | UUID → School | |
| label | String (1–40) | e.g. "3. Stunde", "Große Pause" |
| startTime / endTime | LocalTime | `endTime > startTime` (FR-006) |
| kind | `TEACHING` \| `BREAK` | (FR-005) |

- Slots of one school MUST NOT overlap (touching boundaries allowed) (FR-006).
- Ordering is by `startTime`; no separate ordinal stored.

**SlotDayExclusion**: `(slotId, dayOfWeek)` — the slot does not exist on that teaching day (FR-007). `dayOfWeek` must be a teaching day of the school.

**Derived**: `teachingSlotsPerWeek(school) = Σ over teaching days of TEACHING slots not excluded that day`.

| Field | Type | Rules |

### ClassLevel [`class_level`, `curriculum_entry`] — aggregate root

| Field | Type | Rules |
|-------|------|-------|
| id | UUID | |
| schoolId | UUID → School | |
| identifier | String (1–10) | Unique per school, e.g. "5", "6", "EF" (FR-010) |
| curriculum | List<CurriculumEntry> | At most one entry per subject |
| version | Int | |

**CurriculumEntry**: `(classLevelId, subjectId, periodsPerWeek: Int ≥ 1)`; subject must belong to the same school (FR-011).

**Warning (not blocking)**: Σ periodsPerWeek > teachingSlotsPerWeek(school) → readiness issue `LEVEL_EXCEEDS_GRID` (Acceptance 2.5, FR-024/025).

### SchoolClass [`school_class`] — aggregate root

| Field | Type | Rules |
|-------|------|-------|
| id | UUID | |
| classLevelId | UUID → ClassLevel | Exactly one level (FR-012) |
| suffix | String (1–5) | Unique per level, case-insensitive; display name = level identifier + suffix, e.g. "6b" (FR-012) |
| priorityWeight | Int (1–100) | Default 10 = equal weight for all classes (FR-015) |
| version | Int | |

- **Suffix proposal** (FR-013): smallest letter `a..z` not used in the level; if all used, no proposal (planner enters one).
- **Curriculum** (FR-014, R9): not stored. `ClassCurriculumResolver.curriculumOf(class)` returns the level's curriculum. Extension point for later per-class adjustments.

### Teacher [`teacher`, `teacher_school`, `teacher_qualification`, `commute_time`, `teacher_unavailability`] — aggregate root

| Field | Type | Rules |
|-------|------|-------|
| id | UUID | |
| name | String (1–120) | Not unique (FR-016) |
| shortCode | String (2–8, upper case letters/digits) | Unique in installation (FR-016, Acceptance 3.2) |
| weeklyLoad | Int ≥ 0 | ≤ Σ teachingSlotsPerWeek over the teacher's schools (FR-018); checked when the teacher is saved; hard upper limit (FR-022) and target the scheduler tries to reach (Pareto objective, later feature). A later grid reduction does not re-validate it — see `TEACHER_LOAD_EXCEEDS_GRID` |
| schoolIds | Set<UUID → School> | ≥ 1 (FR-019) |
| qualifiedSubjectIds | Set<UUID → Subject> | Each subject must belong to one of the teacher's schools (FR-017) |
| commuteTimes | Set<CommuteTime> | See below (FR-020) |
| unavailability | Set<(dayOfWeek, slotId)> | Slot belongs to one of the teacher's schools and exists on that day when entered (FR-021). Entries for a day that is later removed from the teaching days are kept but ignored |
| version | Int | |

**CommuteTime**: `(teacherId, schoolAId, schoolBId, minutes: Int ≥ 0)`; stored with `schoolAId < schoolBId` so each pair exists once; both schools must be in `schoolIds`.

**Completeness**: A teacher with ≥ 2 schools is *incomplete* while any pair lacks a commute time (Acceptance 3.5) → readiness issue, saving still allowed.

### UserAccount [`user_account`, `account_school`] — aggregate root

| Field | Type | Rules |
|-------|------|-------|
| id | UUID | |
| username | String (3–60) | Unique, case-insensitive |
| role | `PLANNER` \| `TEACHER` | Only `PLANNER` may access master data (FR-028) |
| active | Boolean | Deactivated accounts cannot log in (FR-032) |
| schoolIds | Set<UUID → School> | ≥ 1 at all times, for both roles (FR-031a). Planners: data access limited to these schools (FR-028a); creating a school adds it automatically. Teachers: the schools they belong to |
| version | Int | |

**Invariant (FR-033)**: every school with at least one assigned planner keeps ≥ 1 *active* assigned planner; deactivating, downgrading to `TEACHER` or unassigning that planner is rejected.

**Manageability (FR-032a)**: account `a` is manageable by planner `p` iff `a.schoolIds ⊆ p.schoolIds`. Only manageable accounts are listed and can have role, schools, active flag or password changed by `p`; schools added to `a` must be in `p.schoolIds`. Every user may change their own password.

**Installation (FR-031)**: with an empty database, the first School and an initial `PLANNER` assigned to it are created together.

### PasswordCredential [`password_credential`]

| Field | Type | Rules |
|-------|------|-------|
| accountId | UUID → UserAccount | One per account |
| passwordHash | String | bcrypt, cost 12 (R7); never logged or rendered; plain password ≥ 10 characters (FR-034) |

Kept separate from `UserAccount` so single sign-on can later add an `ExternalIdentity (accountId, provider, subject)` without changing accounts or roles (FR-035, R6).

### Access rules (FR-028a – FR-028c)

| Data | Visible to planner | Changeable by planner |
|------|--------------------|-----------------------|
| School and everything owned by it | assigned to the school | assigned to the school |
| Teacher (general: name, shortCode, weeklyLoad) | assigned to ≥ 1 of the teacher's schools | same |
| Teacher qualifications / unavailability | for subjects / slots of assigned schools | same |
| Commute time | if ≥ 1 of the two schools is assigned | same |
| Teacher's school assignments | all of the teacher's schools (names only) | add/remove only own schools |
| Teacher deletion | — | only if all of the teacher's schools are assigned (FR-028c); otherwise "remove from own schools" |

## Deletion rules (FR-023)

Deletion is blocked while dependants exist. The blocking dependants are returned as a business error: entries the planner may see are listed by `(type, display name)`, entries of other schools are only counted (constitution III, R10).

| Deleting | Blocked by |
|----------|-----------|
| School | any Room, RoomFeature, Subject, ClassLevel, TimeSlot, or Teacher assigned to it; any UserAccount for which it is the only school (FR-031a) |
| RoomFeature | Room offering it, Subject requiring it |
| Room | — (no dependants in this feature) |
| TimeSlot | never blocked (grid reductions are always saved, spec clarification); its SlotDayExclusions and the teacher unavailabilities referencing it are deleted with it, and the confirmation page states how many unavailabilities are removed |
| Subject | CurriculumEntry, Teacher qualification |
| ClassLevel | SchoolClass |
| SchoolClass | — |
| Teacher | not blocked by dependants; requires access to all of the teacher's schools (FR-028c) |

**Remove teacher from own schools (FR-028c)**: removes the acting planner's schools from `schoolIds` together with the qualifications for those schools' subjects, unavailabilities in those schools' slots and commute times involving those schools. If no school would remain, this is a full deletion and requires access to all schools (which is then the case).

## Readiness issues (FR-024)

Computed in the domain from one school's data (teacher rules: teachers assigned to that school); never persisted.

| Code | Condition | Refers to |
|------|-----------|-----------|
| `SUBJECT_NO_SUITABLE_ROOM` | No room of the school offers all required features of a subject used in any curriculum | Subject, missing features |
| `SUBJECT_NO_QUALIFIED_TEACHER` | Subject in a curriculum, no teacher of the school qualified | Subject |
| `SUBJECT_TEACHER_CAPACITY_SHORTFALL` | Σ required periods of the subject over all classes (via `curriculumOf`) > Σ weeklyLoad of qualified teachers of the school | Subject, shortfall in periods |
| `LEVEL_EXCEEDS_GRID` | Σ periods of a level > teachingSlotsPerWeek | ClassLevel, excess |
| `TEACHER_WITHOUT_QUALIFICATION` | Teacher has no qualified subject | Teacher |
| `TEACHER_ZERO_LOAD` | weeklyLoad = 0 | Teacher |
| `TEACHER_LOAD_EXCEEDS_GRID` | weeklyLoad > Σ teachingSlotsPerWeek over the teacher's schools (e.g. after a grid reduction) | Teacher, excess |
| `TEACHER_MISSING_COMMUTE_TIME` | ≥ 2 schools and a pair without commute time | Teacher, school pair |

Capacity is an upper-bound estimate: a teacher qualified for several subjects counts fully for each, so a shortfall is a definite problem while absence of a shortfall does not guarantee feasibility.
